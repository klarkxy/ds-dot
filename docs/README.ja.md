# ドロシー（dot）

[English](../README.md) · [简体中文](README.zh-CN.md)

![スーツケースと傘を手に到着し、プロジェクトの調整を始めるドロシー](images/dot-arrival.png)

ドロシー（`dot`）は、DeepSeek Harness（DSH）向けの常駐コーディネーターです。専用のサイドバーパネルから話しかけるだけで、ワークスペース管理、複数セッションをまたいだタスクの割り当てと検証、定型的な承認や質問への対応、リマインダー設定、さらにペルソナや呼び方のカスタマイズまで一括して任せられます。

## インストール

DSH `0.2.2-rc.5` 以降が必要です。使用中のプロファイルに追加してください：

```sh
dsh plugin --profile web add ds-dot
```

案内が表示されたらプロファイルを再起動します。プレリリース版は `ds-dot@next`、特定バージョンの固定は `ds-dot@<version>` を指定してください。

インタラクティブカードは Deep View 同梱のため、インストール直後から利用できます。必要に応じて次の補助プラグインも併用できます：

- `@klarkxy/dsh-dev-index`：DSH ドキュメントおよびプラグインレジストリの検索
- `@klarkxy/dsh-model-picker`：設定画面での検索付きモデルピッカー

## 日常的な使い方

サイドバーの **プラグイン**・**自動化** の隣にある **ドロシー** を開き、テキストや画像（PNG、JPEG、WebP、GIF 対応）で依頼内容を伝えます：

```text
D:\work\site にワークスペースを作成し、ドキュメントページのリンク切れを修正して。変更内容も教えて。
```

- **タスクの委任と進行管理：** ドロシーは通常の DSH セッションを起動して作業を割り当てます（書き込み対象パスが重ならないタスクは並列実行します）。各ランのレポートを照合し、成果物ファイルは読み取り専用で自ら開いて確認できます。完了処理では実行レポートまたは成果物ファイルを必ず根拠として示し、任意の独立レビューランも読み取り専用です。同じ要件で失敗が 3 ラウンド続くと作業を止め、あなたに判断を仰ぎます。実行中でも文脈の補足、要件の変更、一時停止・キャンセルが可能で、完了処理の前に自分で確認するよう指定することもできます。

- **承認と質問の代理対応：** 対象範囲は「担当タスクのみ」または「すべてのセッション」から選べます。既定値（承認「ドロシー」、質問「彼女が決める」）では、目標内の可逆な選択について取り決め・会話履歴・ワークスペース状況を確認したうえで彼女が判断し、すでに認可済みの作業は聞き直しません。推測がどれほど確からしくても欠けている認可の代わりにはならず、不可逆・外部・費用を伴う操作には明示的な認可が必要です。次の承認は必ずあなた自身へ回されます：表示が省略されたリクエスト、または高リスクパターンに一致するコマンド——サンドボックス昇格、公開・プッシュ系コマンド、再帰的・破壊的な削除（コンテナ・Kubernetes リソース・SQL DROP を含む）、認証情報や `.env` の参照、リモートダウンロードをシェルへパイプ実行する操作、サブエージェントのシェル実行、読み取り専用実行での書き込み。静的検査は特定パターンのみを対象として網羅的ではないため、残りのリクエストは認可範囲と影響度に基づいて彼女が判断します。あなたに判断を仰ぐ際は推奨案を 1 つ添え、沈黙を同意として扱うことはありません。承認を「私」に切り替えれば全件がカードで転送され、質問を「私に確認」または「関与しない」にした場合は元のセッション上で直接回答できます。

- **セッション監視と履歴検索：** 自分で開いた既存セッションの追跡、実行中タスクの一括点検、過去セグメントやタスク履歴の横断検索も依頼できます。

- **リマインダー設定：** 「30 分後にテスト結果を確認して」「平日の毎朝 9 時に夜間ビルドを要約して」のように自然な言葉で登録でき、セグメント引き継ぎや DSH の再起動をまたいで保持されます。既存リマインダーと完全に重複する登録は拒否されます。

- **レシピの再利用：** 週次レポート、依存パッケージ更新、トリアージなど、繰り返し発生する種類のタスクについて、満足のいった納品をバージョン管理された**タスクレシピ**として保存できます（直接定義してもらうことも可能です）。あなたの依頼や設定済みのリマインダーから再実行する際、作業指示はレシピから埋められるため、その回に固有の内容だけ伝えれば足ります。レシピ自体が原因で実行が失敗した場合、ドロシーは失敗内容を理由として記した改訂を加え、各リビジョンは受理・キャンセルの実績で比較されるため、悪化したリビジョンは以前のものへ戻せます。

ドロシーは常にあなたの言語で応答しつつ、成果物は指定言語またはプロジェクト既存の言語に合わせて作成します。返答はプレーンなテキストとしてストリーミング表示され、カードは表・選択肢・承認の転送など構造が役立つ場面に限られます。会話が長くなると、進行中のタスク・リマインダー・記憶を維持したまま自動的に新しい **セグメント** へ引き継がれます。

## パネルと設定

### タスク

パネル上部の **タスク** からドロワーを開き、*すべて*・*要対応*・*進行中*・*監視・リマインダー* で絞り込めます：

- 納品ファイルや検証メモを確認し、レビュー待ちの作業を受け入れまたは差し戻しできます。
- 実行元セッションへの移動や、不要になったリマインダーの削除も行えます。

### 設定

パネル右上の歯車アイコンから **設定** を開きます：

- **ドロシーのモデル** と **バックグラウンド振り返り**（1 日 1 回まで、新しい会話があるときのみ、モデルターンを消費）を切り替えます。
- **セッション引き受け** で *対象範囲*、*権限の承認*、*モデルからの質問*、*タスク権限* を設定します。
- **割り当てタスク** で *使用可能なタスクモデル* と待機中の *定期チェック* 間隔（未完了の作業が前回から変化したときだけ実行され、各チェックはモデルターンを 1 回消費。`0` で無効）を設定します。
- 各設定項目の鍵アイコンをロックするとドロシーからの変更提案を禁止でき、ロック解除中は承認制の変更提案を受け付けます。

また DSH プラグイン設定から、`homeDir`（ドロシー専用ワークスペースとセッションの保存先。空欄時は DSH ホーム配下の `dot` フォルダ）および `approvalGraceMs`（承認通知の猶予ミリ秒、既定値 `10000`。この間に元のセッションで解決された承認はドロシーを起動しません）を調整できます。

### ペルソナ

**ペルソナ** タブでは、呼び方や話し方をカスタマイズし、2 層の記憶を管理できます：

- **取り決め：** あなたが定めた常駐ルールをそのままの言葉で保持します。認知と競合した場合は常に優先され、直前の保存を取り消すことも可能です。
- **認知：** 作業スタイルや好みについてドロシーが蓄積した理解です。直接編集できるほか、過去バージョンの確認・復元にも対応しています。

### コンテキストと実行軌跡

- **コンテキスト：** トークン使用量、固定された **プロンプトセクション**、キャッシュヒット率を確認でき、手動で新しい **セグメント** を開始することもできます。
- **実行軌跡：** ターンごとのステップ、ツール呼び出し、バックグラウンド振り返りの履歴を検索・閲覧できます。

### 出荷時設定にリセット

設定画面の下部から、消去対象（追跡中タスク、変更とラン、リマインダー、タスクレシピ、提案、カード、アーカイブされるセッション（彼女自身の会話・バックグラウンドセッションを含む）、取り決め、認知、設定）をプレビューしてから初期化できます。あなた自身のセッション、プロジェクトファイル、ホストのペルソナは変更されません。

## GitHub イベント（任意）

ドロシーは Pull Request、Issue、コメント、レビュー、CI の実行、デフォルトブランチへの push、Release を追跡できます。イベントはまず永続的な受信箱に入り、再配信されたものは破棄され、同じ PR や Issue のイベントはまとめられ、ドロシーの手が空いたときに届きます。イベントの内容は常に信頼できないデータとして扱われ、確認や相談のきっかけにはなっても、それ自体が何かを許可することはありません。ping、star、fork、watch、check run、成功・スキップ・neutral となった CI 結果は除外されます。どのリポジトリとイベントを受け取るかは GitHub の webhook 設定で選びます。

1. 同じプロファイルに webhook ランタイムと GitHub アダプターを、DSH と同じバージョンでインストールします（npm の `latest` タグはまだ古い 0.1 系を指しています）：

   ```sh
   dsh plugin --profile web add @deepseek-ai/dsh-webhook@0.2.2-rc.5 @deepseek-ai/dsh-webhook-github@0.2.2-rc.5
   ```

2. 次のオーバーレイを `$DSH_HOME/profiles/web/dot-github/cordis.yml`（`DSH_HOME` 未設定時は `~/.dsh`）として保存します。`127.0.0.1:3081` に `POST /github` だけを受け付ける別のリスナーを開きます：

   ```yaml
   - insert:
       - id: webhook-runtime
         name: '@deepseek-ai/dsh-webhook'

       - id: github-webhook-ingress
         name: cordis:group
         group: true
         isolate:
           webServer: true
         config:
           - id: github-webhook-server
             name: '@deepseek-ai/dsh-host-webserver'
             config:
               host: '127.0.0.1'
               port: 3081

           - id: github-webhook-adapter
             name: '@deepseek-ai/dsh-webhook-github'
             config:
               source: primary-github
               path: /github
               secretEnv: DSH_GITHUB_WEBHOOK_SECRET
               maxBodyBytes: 1048576
   ```

3. 十分に長いランダムなシークレットを `DSH_GITHUB_WEBHOOK_SECRET`（環境変数または `$DSH_HOME/.env`）に設定し、再起動後も同じ値を保ったまま、オーバーレイ付きで DSH を起動します：

   ```sh
   dsh web --patch "${DSH_HOME:-$HOME/.dsh}/profiles/web/dot-github/cordis.yml"
   ```

4. TLS リバースプロキシまたはトンネル経由で `127.0.0.1:3081/github` だけを公開します。ポート 3080 の UI は非公開のままにします。

5. リポジトリの GitHub webhook 設定で、Payload URL に `https://<your-host>/github`、Content type に `application/json`、Secret に同じシークレットを指定し、ドロシーに届けたいイベントを選びます。

## 旧バージョンからのアップグレード

リマインダー、取り決め、認知、設定、現在のタスク記録は引き継がれます。以前のチケット記録、`memory.md` などのメモファイル、旧カスタムポリシーのテキスト、削除された設定フィールド名は読み込みも移行もされません。

## ご利用にあたって

- 書き込み範囲はドロシーが割り当てたタスク間の競合を防ぐための仕組みであり、外部エディタや OS プロセスをロックするものではありません。
- 読み取り専用タスクの境界保護には、ツール実行前ガードとあわせてホスト側の権限制御が必要です。
- 成果物の受け入れはタスクの完了処理のみを行い、プッシュ・公開・課金操作を自動的に許可するものではありません。
