# 桃乐丝（dot）

[English](../README.md)

![桃乐丝带着行李和雨伞抵达，准备帮你协调项目](images/dot-arrival.png)

DeepSeek Harness 的常驻调度管家桃乐丝，简称 dot。在她自己的面板里和她对话：她管理工作区、启动任务、跟进进度、处理审批，并向你汇报。你只需要在一个对话里交流，而她负责调度你的项目。

她的聊天风格轻松且真诚。工作进行时，她会保持任务推进并提供清晰的进度更新。你可以在设置里自定义她的人设和称呼。

## 安装

从 npm 装进你正在用的 profile：

```sh
dsh plugin --profile web add ds-dot
```

DSH 提示时重启 profile。需要固定版本时使用 `ds-dot@0.1.0`。Deep View 会一起装上，负责绘制卡片、确认框和图表；这一版依赖 npm 上已发布的 `@klarkxy/dsh-deep-view@0.2.1`。0.3.0 的数学图、节点图、地图和数据探索还没上 npm，在它发布前桃乐丝只画得出 0.2.1 支持的卡片。若同一 profile 装了 `@klarkxy/dsh-dev-index`，桃乐丝还能用它的文档和插件检索工具。若装了 `@klarkxy/dsh-model-picker`，设置里的模型选择会走那个搜索器。

需要安装源码修订时，使用 `github:klarkxy/ds-dot#<commit>`。如果 pnpm 提示需要允许构建，在该 profile 的 `pnpm-workspace.yaml` 的 `allowBuilds` 下加入 `ds-dot: true`，再执行安装。

本地对着这份源码联调时，用 `link:` 安装，让 DSH 使用整棵源码树（含 `src`），而不是只拷贝 `lib`：

```sh
dsh plugin --profile web add link:H:\Code\ds-dot
```

在仓库里跑 `pnpm watch`，改 `src/` 时 `lib/` 会跟着重建。普通路径或 `file:` 安装仍按包的 `files` 拷贝，现在其中已包含 `src`，便于对照源码调试。

## 使用

点侧栏「插件」「自动化任务」那一列里的 **桃乐丝**。当面板打开时，她的鲸鱼图标会变为粉色。该面板是她的专属对话环境，独立于你的工作区会话列表。

直接告诉桃乐丝你要做什么，例如：

```text
在 D:\work\site 建个工作区，开一个任务：修好文档页里失效的链接，做完告诉我改了什么。
```

桃乐丝将你的请求转换为持续的工作。对于明确的请求她直接开工；对于复杂的工作，她保持这个 Change 打开，直到每一项要求都被验证。她的管理方式如下：

- **变更与要求**：每个目标成为一个 Change，带自己的 requirements 和 steps，行为约束随输入一起走；并行上限是执行配置，单独改标题或上限不会生成新的输入版本。改变范围的后续指令会生成新的输入版本——旧结果不会冒充新版本的验收。不改变范围的补充上下文会按当前输入版本投递给活动中的 Run，过期版本会被拒绝而不会误投。暂停会阻止新 Run 启动但让进行中的 Run 完成；取消拒绝新工作并逐一收拢进行中的 Run。
- **运行协调**：她为每次 Run 预约所需的写入范围，在首个写指令前采集施工前基线，只有确认停止后才释放该范围。基线采集失败时，只释放这次启动新建且尚未启动的预约；已经选中的预约留着重试，Change 不会被取消。互不冲突的 Run 可以并行。
- **步骤归属**：一个步骤只有在覆盖它的 Run 于当前输入上产出可读结果时才记为完成——后一个 Run 在同一路径写出的文件不会记在前一个 Run 名下。
- **验收**：Change 收口前，她对照实际交付逐项核对要求并附证据。简单的单 Run 任务可以一步完成检查和收尾，证据与版本检查保持一致。仅有摘要不会被算作通过。被退回的交付要先返工、重新核验，才能收口；连续三次失败会升级给你。
- **人工过目**：当你要求先过目时，她等待你通过卡片或按钮给出的版本匹配决定。过期或已撤销的请求不被当作决定。
- **工作区管理**：她新建或复用工作区，为每个 Run 写好完整的第一条指令，包含目标、范围和验收要求。
- **代理选择**：她为每个 Run 挑选合适的预设：通用任务用默认预设，脚本任务用 `ptc`，插件开发任务用 `cordis`。
- **专属环境**：她维护一个自己的工作区用于调研或 DSH 管理任务，通过 DSH 主目录下的 `dot` 文件夹访问。
- **会话跟踪**：她可以按你的指示启动、停止或关注会话。
- **智能更新**：她汇总工作动态、审批与提问，并在空闲时高效送达。
- **审批管理**：她接管所有会话的审批请求，常规审批自动完成，涉及高风险变更（如删除外部数据、发布、推送、范围变更）时会通过卡片征求你的意见。

桃乐丝的每一次交互都以一张卡片结束。报告用展示卡呈现文字、表格或图表；需要决策时，交互卡提供选项、确认按钮或表单。

点击面板顶部的「任务」即可打开工作看板。它列出每个 Change 的版本、Run、占用者、检查和收口状态，以及需要你的动作——接受、退回、过目或补收口。看板会随后台工作事实的变化刷新：每个 Run 的写入范围、投递与验收证据都能展开查看，状态标签按界面语言显示。绑定到当前验收的证据可以只读打开——未绑定、过期或缺失的条目会明确提示失败而不是显示内容，它不是通用文件浏览器。长内容先显示预览，可按需查看全文；详情中也会列出依赖、缓存、源码链接等未纳入快照的路径。未知、被拒绝、未证实的状态不会被画成成功。只有当检查和资源清理都确认无误时，Change 才显示「已完成」；会话自称完成不算数。

她还能处理定时提醒。你可以要求她「半小时后提醒我」或「每个工作日早上九点汇总进度」。这些提醒在对话分段、会话重启甚至 DSH 重启后依然生效。

## 设置

点击齿轮图标打开包含「设置 / 人设 / 上下文 / 轨迹」的抽屉。你可以个性化调整她的模型、审批习惯、任务权限以及性格。

- **人设**：自定义称呼与语气。
- **约定**：记录你的常驻要求与规矩。
- **认知**：桃乐丝对你的理解，随协作自动更新。
- **上下文**：查看当前分段的 Token 用量与提示词组成。
- **出厂设置**：把桃乐丝恢复到刚安装时的状态。会清掉她自己的工作数据、她创建的会话、提醒、审批和设置；未全部完成时会说明剩余步骤，并提供重新预览重试的入口。你本人的会话、项目文件和宿主人格不会动。

## 限制

- **工作模型**：Run 是普通会话的工作记录，不是子代理。Run 中的文件和 shell 操作有记录可查；Change 记录跟踪其输入、范围和验收。
- **合作式并发**：写入范围指导桃乐丝的分派，并不强制阻止所有工具、编辑器或外部进程。被拒绝的预约保持排队，不会覆盖共享文件。
- **基线与证据**：写 Run 首发前需要已发布的施工前基线。采集失败时只释放这次新建且未启动的预约。验收需要已采集的交付快照加逐项明确检查与证据；摘要不算通过，不完整的保持未证实，不会收口。
- **过期或未知结果**：过期的输入、决定或按钮会被拒绝而非应用。无法确认的停止保持占用其范围，直到对账完成。
- **资源覆盖**：她可以自己上网核对一条当前事实。需要多步检索或持续研究时，仍交给 Run。她自己的记录限于她的对话和她管理的工作。
- **约定与认知**：通过「人设」页管理，确保你的偏好得到尊重。
- **审批路由**：用户审批模式下，请使用对应请求的确认卡；过期卡片不能批准后来的请求。
- **用户答复提问**：用户答复提问模式下，请在原会话中回答原始问题。
- **后台回复**：后台回合结束时如果没有可用卡片，普通文本仍会显示。
- **任务权限**：宿主无法强制只读权限时，只读 Run 不会启动。运行中的会话在当前权限可核验时可接收补充上下文；否则须先停止会话并应用当前权限，才能继续。
- **取消任务**：确认关联 Run 停止之前，Change 会继续持有其写入范围。
- **尚未实测**：桃乐丝的新工作模型已通过单元测试、UI 层测试和隔离宿主接缝验证。真实共享工作区的多会话协作、现场队列/结算核验、真实浏览器中的看板行为和完整的模型在环行为仍在验证中——请把它当作进行中的工作，而非已发布的保证。
