# 任务配方：第一期刻意留白的部分

第一期已落地范围：配方的保存 / 修订 / 恢复 / 删除（`dot_recipe`）、建单与派发时套用配方（`dot_task`）、按修订归并的验收 / 取消实绩、修剪前回写结果，以及出厂重置计数。当前修订历史上限 10 条、实绩上限 50 条，先观察真实使用再决定是否扩容。

## 后续候选

- **影子阶段（Shadow stage）：** 新配方或新修订在前 N 次验收通过前强制只读或仅出草稿，防止改坏的修订直接获得写权限。（需先明确「验收通过」在 closeout 还是人工确认阶段计数。）
- **回放评测（Evals）：** 保存配方时附带样本输入，新修订先在只读运行中回放全部样本，通过后才允许引用派发。依赖无副作用的评测运行形态，可与影子阶段二选一或串联。
- **反思主动提出修订建议：** 后台反思定期读取配方实绩（`accepted`/`cancelled`、`failedRounds`），发现某修订明显退步时主动建议修订或回退，而不是等失败后才临场修改。
- **Tasks 面板的配方视图：** 目前配方仅以 `dot_recipe` 文本输出呈现；后续可在任务抽屉增加专门分组，展示配方列表、当前修订、实绩统计与进行中任务。
- **提醒 / 收件箱规则直接绑定配方：** 目前提醒需先唤醒 dot 再由她建单派发；未来可允许特定提醒或收件箱规则直接按指定配方建单派发，省去一轮对话，适合完全例行的任务。
- **配方级锁：** 类似设置项的锁形开关，锁定后禁止 dot 修订或删除该配方，防止无人值守时把成熟配方改坏。
