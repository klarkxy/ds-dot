# 任务配方：第一期没做的部分

第一期范围：配方的保存 / 修订 / 恢复 / 删除（`dot_recipe`）、创建与派发时套用配方（`dot_task`）、按修订归并的验收 / 取消实绩、修剪前回写结果、出厂重置计数。修订历史上限 10、实绩上限 50，先跑起来看真实使用再决定要不要扩容。

## 后续候选

- **影子阶段（shadow stage）**：新配方或新修订在前 N 次验收通过前强制只读或仅出草稿，防止一次改坏的修订直接拿到写权限。需要先想清楚"验收通过"在哪个阶段计数（closeout 还是人工确认）。
- **回放评测（evals）**：保存配方时附带样本输入，新修订先在只读运行里回放样本，全部通过才允许被引用派发。依赖一个没有副作用的评测运行形态，和影子阶段二选一或串联。
- **反思提出修订建议**：反思流程定期读配方实绩（accepted/cancelled、failed rounds），发现某修订明显退步时主动提议修订或回退，而不是等一次失败后才由 dot 临场改。
- **Tasks 面板的配方视图**：目前配方只有 `dot_recipe` 的文本输出。可以在 Tasks 里加一个分组，列出配方、当前修订、实绩统计和正在飞行的任务。
- **提醒 / 收件箱规则直接绑定配方**：现在提醒要唤醒 dot 再由它建任务。可以让某类提醒或收件箱规则直接以指定配方建单并派发，不经过 dot 的一次对话，适合完全例行的任务。
- **配方级锁**：类似设置项的锁定开关，锁定后 dot 不能修订或删除该配方，防止它在无人值守时把一份成熟配方改坏。
