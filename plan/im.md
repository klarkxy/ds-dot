# IM 接入

## 动机

让用户可以直接在飞书、Telegram、Slack 等即时通讯工具里接收桃乐丝的提醒与动态，也能随时发消息和她协作。

## 当前结论

- **传输层：** 优先采用由本机主动连出的长连接方案（飞书长连接、Slack Socket Mode、Telegram `getUpdates`、Discord Gateway），无需暴露公网地址。
- **架构边界：** 适配器作为独立插件实现，所有外部事件统一经由 dot 的收件箱入口 `submitInbox` 接入，dot 本体不写任何 IM 协议代码。

## 分两期推进

1. **第一期（只接收）：** IM 消息进入收件箱，与 GitHub 事件同等看待，按不可信外部数据处理。
2. **第二期（双向交互）：** 支持 dot 向 IM 回复消息并在 IM 内完成审批。由于 IM 将成为第二对话入口，需单独设计外部副作用边界、双端回复归属与面板状态同步。

## 权限模型（动手前必须先定）

- 仅经过绑定的**本人账号**消息，才能与面板输入同等对待；群聊及其他人的消息一律视为不可信数据，绝不构成授权。
- 即使是本人账号，审批也只认明确的结构化动作（如交互按钮或显式指令「批准 #id」），不从自然闲聊中推断同意。
- 绑定流程：面板生成一次性绑定码 → 在 IM 中发送给机器人 → 持久化记录已绑定账号 ID。

## 待定事项

- 凭据托管方式（应引用 DSH 凭据体系，不落入 dot 自身存储）。
