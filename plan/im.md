# IM 接入

## 动机

在飞书、Telegram、Slack 等 IM 里收到 dot 的消息，也能直接和她说话。

## 当前结论

- 传输层优先用由本机主动连出的长连接：飞书长连接、Slack Socket Mode、Telegram `getUpdates`、Discord Gateway。不需要公网地址。
- 适配器做成独立插件，事件统一经 dot 的收件箱入口 `submitInbox` 进入（见收件箱实现），dot 本体不写任何 IM 协议代码。

## 分两期

1. **只接收**：IM 消息进收件箱，和 GitHub 事件一样当作外部事件，按不可信数据处理。
2. **双向**：dot 往 IM 回消息、在 IM 里处理审批。IM 会因此变成第二个对话入口，要单独设计外部副作用、回复由哪一端负责、和面板怎么同步。

## 权限模型（必须先定）

- 只有绑定过的本人账号发来的消息，才能和面板里的输入同等对待。群聊、其他人的消息一律是不可信数据，永远不构成授权。
- 即使是本人账号，审批也只接受明确的结构化回复（按钮，或者"批准 #id"），不从闲聊里推断批准。
- 绑定流程：面板生成一次性绑定码 → 在 IM 里发给机器人 → 记下账号 ID。
