# 收件箱：第一期没做的部分

第一期范围：GitHub webhook（经 `@deepseek-ai/dsh-webhook` 规则）→ dot 收件箱（持久化、去重、按对象合并）→ 空闲时唤醒 dot。
订阅范围由用户在 GitHub 的 webhook 设置里选事件和仓库决定，dot 只做固定的噪声过滤。

## 后续候选

- **订阅 / 静音工具**：让 dot 或用户按仓库、事件类型静音，不用回 GitHub 改设置。等真的出现噪声问题再做。
- **看板里的收件箱列表**：现在外部事件只作为聊天里的通知出现。之后可以在 Tasks 里加一个分组，查看最近事件和处理状态。
- **事件与任务关联**：dot 为某个 PR 派出任务后，同一个 PR 的后续事件（新提交、CI 结果、评论）直接关联到该任务，而不是作为独立通知。
- **更多 GitHub 事件类型的专门摘要**：第一期只为常用事件写了摘要，其余走通用的一行格式。
- **其他来源**：IM（见 im.md）、通用的签名 webhook（任意 JSON + HMAC）。
- **保留策略设置**：第一期固定保留最近 N 条已投递事件。
- **合并时保留事件类型历史**：同一对象的待投递记录合并后只保留最新一条事件的类型和摘要。比如 PR 先 opened 再收到评论，dot 只看到 `issue_comment.created ×2`，"刚开的 PR"这个信息丢了。可以在记录上保留出现过的类型列表。
- **README 和安装说明**：第一期没写面向用户的文档。用户需要安装 `@deepseek-ai/dsh-webhook` 和 `dsh-webhook-github`，并在 overlay 里挂上独立的 WebServer 和适配器（参考官方 github-review 示例，去掉其中的评审规则）。
- **去重窗口按数量计**：只保留最近 200 条已投递记录、每条合并记录最多记 50 个 delivery id。手动点 GitHub "Redeliver" 重放较旧的投递会按新事件入库；可以考虑按时间保留。
